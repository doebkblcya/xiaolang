# 维护、交付与清理

更新：2026-10-24。当前部署版本与待观察事项见[实现进度](../实现进度.md)，参数见[总体链路与运行参数](../总体链路与运行参数.md)。

## 代码与交付物

| 位置 | 性质 | 更新方式 |
| --- | --- | --- |
| src/ | TypeScript 实现；其中部分构建为独立业务外挂。 | 改动后按构建结果判断宿主或外挂范围，不能看到 src 就一律重建部署镜像。 |
| examples/plugins/panel/ | 管理面板外挂源码、网页和插画。 | 普通页面改动同步 panel 目录，按现行流程重启并刷新。 |
| dist/host/ | 可由源码重建的宿主文件。 | 不提交；宿主接口、运行环境或依赖变化时构建新镜像。 |
| dist/plugins/ | 可由源码重建的独立插件包。 | 只更新改变的对应插件目录，复用当前兼容宿主。 |
| plugins/ | 本机或 NAS 的挂载插件工作区。 | 不是新的源码副本，默认被 Git 忽略。 |
| data/ | SQLite、设置以及私人基线等持久内容。 | 保护原数据和凭证，不能为清理构建产物而整目录删除。 |
| Docs/归档、Docs/初期调研 | 历史决策与发布记录。 | 保留来源，明确历史参数已过期，不冒充当前使用指南。 |

`npm run build` 修补固定版本 QQ SDK，编译 TypeScript，并生成宿主和外挂产物。`dist/plugins/_runtime.mjs` 在构建目录连接公共 API，实际挂载工作区的桥接入口由宿主生成。运行镜像不包含已经迁出的业务实现，不通过“外挂转调镜像同名代码”假装解耦。

```sh
npm ci --ignore-scripts --no-fund --no-audit
npm run build
```

固定 SDK 版本及构建补丁是交付的一部分；不要跳过构建补丁而宣称与线上行为一致。普通文档整理无需构建或调用模型。

## NAS 更新流程

1. 确认改动属于宿主、哪些外挂或仅配置；保留运行配置、数据库、证书挂载、访问 Key 和既有数据。
2. 使用飞牛 Skill 及已有 trim-cli OAuth 授权，不因网页会话过期要求重新登录飞牛网页。CLI 授权与网页登录相互独立。
3. 更新外挂时只上传对应构建文件／目录；修改公共服务契约或镜像依赖时同步更新宿主。必要时留一份对应文件的回退副本，不长期堆积多轮 release 目录。
4. 沿用 Compose 的环境、端口、资源限制及持久挂载。通过既有流程重启；不为页面改动重建镜像。
5. 只检查容器状态、必要的启动报错和 HTTP 响应。界面操作由用户手动验收；不要额外调用真实模型、发 QQ 测试消息或执行真实提醒。
6. 本次更新正常后，清理已不用的下载包和辅助容器；镜像目标保留当前及上一版，删除前确认没有容器引用。回退方案未核对前不批量 prune。

NAS 应用目录沿用现有 `xiaolang` Compose 项目。`data/`、`plugins/` 和证书分开挂载，当前内存上限 512 MiB。内网 HTTP 和公网 HTTPS 使用既有端口与鉴权；完整访问配置可查归档中的旧 README 技术说明，并以当前配置接口为准。

GitHub Actions 继续按既有流程检查、构建镜像并发布 `xiaolang-plugins.tar.gz` 及 SHA256SUMS；两个交付物可独立下载。镜像修订标签仅代表宿主，必须另外记录外挂更新基线。只修改文档不需要更新 NAS。

## 配置与访问

基础配置和后台 `settings.json` 分工沿用原实现。面板保存带 revision 校验；保存后应用并重启，启动失败按既有规则回退。普通插件停用不删除配置或业务数据。更换插件代码不要求用户重新填写密钥。

面板访问 Key、Cookie 和同源写入令牌有各自用途；不能为了调试输出到日志或复制到文档。重启后面板可能要求用原 Key 重新验证，这与飞牛 CLI OAuth 无关。证书由飞牛续期，面板只读挂载并定期重载，不为续期重建镜像。

## 数据维护

业务插件共用 SQLite 文件，但通过所属服务和清理钩子维护自己的表。清理采用宿主 `deleteData` 事务和各插件 cleanup，不直接删一张表就认为结束。协调前有 `xiaolang/before-delete`，提交后发 `xiaolang/data-deleted` 更新缓存；存在正在执行／发送的轮次会拒绝删除，避免旧内容继续参与回复。

删除单条记忆／习惯保留原聊天；删除聊天会清理可追溯的派生内容。旧版本、FTS、向量、召回、摘要及来源抑制的具体副作用见[记忆专题](../专题/记忆与自学习.md#删除副作用与后续评估)。彻底删除没有产品恢复入口；备份副本也含原内容，不能未经明确选择就另存公开审计材料。

如需数据库备份，使用一致性备份机制，或停止写入后同时处理 SQLite 和 WAL；不能只拷贝正在写的主数据库并认为得到完整备份。不要把线上数据库复制到仓库、构建包或测试夹具。面板删除只影响本地记录，不意味着撤回 QQ 已发送消息。

## 临时产物清理边界

可删除：本轮已完成的发布 ZIP／tar／校验文件、临时解包插件、任务专用调研副本、过期截图／日志、一次性脚本和验证数据库，以及可重建的本机 dist。

继续保留：运行中的 NAS 挂载数据、有效配置与凭证、本机依赖、必要回退版本、实际使用的图片及可供编辑的原始插画、生成提示词、公开文档和后续人工复核基线。不要按宽泛的文件名通配清理其他项目，也不要把全部 data 当成测试残留。

2026-10-24 本次整理共清理 22 个已确认的本机临时文件／目录，按文件逻辑大小约 966.5 MiB（约 1.01 GB）：包括两轮镜像发布与解包文件、旧调研副本、验证数据库／脚本、旧截图／日志和可重建 dist。保留插画源文件、配置与凭证及私人复核基线。随后又清理了 2 张完成截图和 1 份临时清理流水，本机 data 仅保留访问 Key 与后续复核基线。NAS 的在线服务和回退资源没有作为本机清理顺带修改。之后用户手动要求复核时，再看新增记忆、学习项和实际召回，不设置自动提醒。

## 文档维护顺序

- 当前参数写入运行参数文档；机制与接入规范写入对应专题；发布结果和未完成验证写入实现进度。
- 历史发布记录移入归档，保持旧记录可追溯；外部接口核对必须标核对日期与账号权限边界。
- 不把尚待真实样本验证的 Prompt 效果写成已完成验收，不把“有日志”写成“相关性完全正确”。
- 私人审计基线与聊天原文留在被 Git 忽略的本机 data；公开文件只写机制及必要的匿名数量。
- README 已在用户另行授权后按对外门面整理，不提供内部开发文档导航；旧版技术内容归档保留。
