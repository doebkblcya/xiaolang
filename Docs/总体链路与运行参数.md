# 小狼总体链路与运行参数

更新：2026-10-20。这里集中说明小狼现在有哪些能力、一条消息怎么走，以及本次 NAS 配置的实际参数。以后在面板改过参数，以面板当前值为准。设计依据见 [主链路](主链路.md)，完成情况见 [实现进度](实现进度.md)。

## 现在能做什么

小狼通过 QQ 官方机器人正式环境的 WebSocket 收消息，在飞牛 NAS 的 Docker 中运行。能聊天、看图、记住事情、学习表达、使用工具、接续群聊、适时插话和定时提醒；有可以查看、配置和删除数据的管理面板。长期记忆全局共享，保留用户、群和时间来源。

当前加载 23 个内置插件、2 个外挂插件。内置／外挂表示代码随镜像提供还是从挂载目录加载，不表示插件能力大小。

| 插件 | 实际负责什么 |
| --- | --- |
| QQ 官方接入 | WebSocket 收消息、平台标识与昵称／群名、私聊／群聊发送与主动推送。 |
| 消息接纳 | 校验、去重、保存所有实际收到的消息，包括没触发回复的消息。 |
| 消息触发 | 私聊、@、触发词，以及群聊的活跃／旁观判断。 |
| 任务调度 | 同会话逐条排队，不同会话有限并发。 |
| 默认聊天编排 | 拼装输入，调用回复模型，执行工具，再继续回答。 |
| DeepSeek 模型 | 普通／流式模型请求、思考参数、超时和有限重试。 |
| 聊天与记忆 | 近期聊天、摘要、长期记忆、混合检索、图片描述与按编号重看。 |
| 人设与学习 | 固定人设和 QQ 回复风格；独立后台学习表达习惯。 |
| 工具注册与执行 | 统一工具接口、参数校验、按真实发言人 ID 鉴权。 |
| 查询时间工具、基础计算工具 | 查询现实时间、进行基础计算。 |
| 网页搜索与阅读 | DeepSeek Search／Fetch，提供网页来源、摘要和正文。 |
| MCP 接入、Skills 接入 | 连接外部工具服务，按需读 Skill 说明／资料；受控执行管理员脚本。 |
| 定时提醒 | 一次性、每天、每周的提醒，创建、查看、取消和到点发送。 |
| 统一发送 | 普通／流式输出、群聊分句、发送记录及回执。 |
| 故障反馈 | 对明确召唤的处理失败，在 QQ 给出中文提示、错误码和轮次编号。 |
| 会话存储 | SQLite 中的聊天、轮次、工具与发送状态。 |
| 日志处理、模型用量统计、运行观察 | 清理敏感日志字段，记录各阶段事件与真实 API 用量，向面板提供数据。 |
| 配置管理 | 参数校验、保存、应用重启及启动失败回退。 |
| Cordis 插件加载器 | 加载外挂插件、管理服务依赖和资源释放。 |
| 管理面板（外挂） | 状态、分会话聊天、记忆、表达学习、工具、提醒、用量及配置。 |
| 终端日志展示（外挂） | 将过程事件输出为中文日志或 JSON，供 Docker 日志查看。 |

表情包原生收发暂时搁置；语音、电脑操作尚未接入。MCP／Skills 的接入能力已有，具体外部服务和 Skill 由后续安装决定。

## 一条消息怎么走

```mermaid
flowchart TD
  QQ[QQ 官方 WebSocket] --> Intake[校验、去重、保存消息]
  Intake --> Trigger{是否需要回复}
  Intake --> Background[后台图片描述；定期记忆提炼与表达学习]
  Trigger -->|私聊、@、触发词| Queue[进入当前聊天的队列]
  Trigger -->|普通群消息| Judge[按活跃／旁观节奏判断是否接话]
  Judge -->|沉默| Wait[继续观察，消息仍已保存]
  Judge -->|接话| Queue
  Queue --> Context[人设、时间与身份、近期聊天、摘要、召回记忆]
  Context --> Model[DeepSeek 回复模型]
  Model -->|需要工具| Tool[鉴权、校验、执行工具]
  Tool --> Model
  Model -->|得到回复| Send[统一发送到 QQ]
  Send --> History[保存已确认回复与回执]
```

一次回复可以调用多次模型：例如先决定调用搜索工具，再根据搜索结果回答。后台记忆、表达学习和图片描述是独立请求，不与聊天请求合并；没有新材料时，不会为了定时器空调用提炼／学习模型。

## 哪些地方调用外部模型

本次已在 NAS 核实上述配置。思考与工具继续请求按 [DeepSeek 官方思考模式协议](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode/)处理；当前轮工具继续请求保留模型返回的思考状态，思考正文不发到 QQ。

外部模型只有两种：DeepSeek `deepseek-flash` 和百炼 `text-embedding-v4`。Search／Fetch 是另外的外部工具接口，不是新增的聊天模型。

| 功能 | 本次思考档位 | 单次输出上限 | 请求时限／重试 |
| --- | --- | --- | --- |
| 聊天回复，包括当条看图与工具后的回答 | high | 8192 Token | 60 秒；最多重试 1 次。流式已输出后不重试。 |
| 判断是否插话 | 关闭 | 256 Token | 8 秒；不重试。 |
| 提炼／更新长期记忆 | high | 8192 Token | 60 秒；最多重试 1 次。 |
| 较早聊天摘要 | high | 8192 Token | 60 秒；最多重试 1 次。 |
| 学习真人表达 | high | 8192 Token | 60 秒；不重试。 |
| 图片短描述，供历史与摘要使用 | high | 8192 Token | 60 秒；最多重试 1 次。 |
| 工具重看历史图片后的回答 | 沿用回复模型的 high | 与聊天回复相同 | 工具取图后交回回复模型，不再单独请求模型转述图片。 |
| 百炼向量化 | 无思考档位 | 返回向量 | 接口时限 15 秒；前台检索只等 2.5 秒，超时降级关键词检索。 |

8192 是思考与最终输出共用的上限，不是每次固定消耗，也不会要求 QQ 回复写满。聊天仍保持简短。high 的实际效果、耗时与开销，通过“模型用量”看板观察。旧配置没有新增摘要／图片描述档位时，仍按原来的关闭思考运行；本次 NAS 已显式配置为 high。

## 什么时候会回，什么时候会等

| 场景 | 当前规则 |
| --- | --- |
| 私聊 | 默认直接回复。 |
| 群 @ 小狼 | 直接回复。 |
| 群消息含“小狼”或“xiaolang” | 句中任意位置命中即直接回复。 |
| 60 秒活跃期 | 新消息约 250 毫秒后判断；连续消息最多收集 1 秒。不必再次 @ 或带触发词。 |
| 旁观期 | 从第一条待判断消息开始等 60 秒，或先攒到 20 条；哪个先到就把这一批交给模型。只有少数消息，到了 60 秒也判断。 |
| 没有新消息 | 不调用插话判断模型。 |

活跃表示判断更及时，不表示每句必回。正常接小狼的话、追问、纠正或调侃，都可以自然接续；群友彼此聊天时，减少可有可无的插话。明确召唤会激活；确认直接接话并成功回复才续期；小狼自己插一句不续期。主动插话已开启，群黑名单当前为空。

判断参考最近 30 条记录，文字预算约 6000 Token；每条最多取 1600 字符。每群最多暂存 50 条待判断消息，全局最多并行 2 个判断。成功回复的每分钟计数达到 6 次时，后续自主判断会等待，明确召唤不受这层限制。

旁观等待和结果过期分开计算：超过 3 分钟的旧消息跳过；判断通过后若再排队超过 30 秒，或期间出现新的明确召唤，则丢弃该次自主回复。不能把旁观所需的 60 秒等待算进 30 秒队列时限。

一批 20 条是共同判断是否参与，不是逐条产生 20 个回复。正式回复以本批最后一条作为触发消息，结合已保存的聊天理解其余内容。正在回复时，新消息继续积累，不同时为同群堆多次判断。

## 上下文、长期记忆和学习

### 回复时带什么

1. 固定人设、QQ 简短表达风格，以及按语境选择的表达习惯。
2. 当前北京时间、发言人 ID／昵称、群或私聊来源。
3. 当前聊天最近最多 100 条原文。用户消息和机器人回复分别算一条，不是 100 轮。
4. 较早摘要、全局检索出的相关记忆，以及图片编号和文字描述。
5. 当前问题；当条附图或本轮通过工具重看的原图。

总上下文预算为 100,000 Token，使用官方分词文件计数文字，并为图片、输出、工具结果与协议留空间。超过预算会减少近期原文，不保证每次都塞满 100 条。记忆和摘要另有合计 5000 字符预算，每轮最多召回 8 条记忆。固定身份不随自动学习改变，人物资料和聊天经历全局共享，来源仍能追溯。

### 后台长期记忆

- 每 60 秒检查新材料；启动时也检查积压。没有新用户消息，不调用提炼模型。
- 每批最多处理 20 条新用户消息，包含没 @、没触发词的消息；参考已经确认的机器人回复和相邻对话。
- 本批新原文约 20,000 字符预算，单条最多 2500 字符；周边对话另约 12,000 字符预算。长消息不是整段无限塞入。
- 模型决定新增、补充、状态替代或忽略；每批最多 12 条候选，并校验人物、原文来源与版本。
- 记忆保存文字、来源、人物、时间和版本。百炼向量存入同一个 SQLite 的向量索引，检索结合关键词、人物和向量，不额外部署向量数据库容器。
- 每次向量请求最多 10 段文本，每段最多 6000 字符；当前维度为 1024。
- 成功才推进处理位置；失败保留材料，下次继续。正在处理时不会重复启动同批任务，没有独立每日提炼次数上限。

### 较早聊天摘要

准备回复时，发现近期窗口之前还有尚未整理的旧记录，就在后台增量合入摘要。本轮不等摘要生成，后续轮次再使用；原始聊天不删除。每批最多 40 条旧记录，单条文字最多取 600 字符，模型目标摘要在 800 字以内；包含图片编号和短描述，不含原图。

### 表达自学习

每分钟检查一次；距上次调用至少 30 分钟，而且至少有 20 条新用户消息，才自动学习。每批最多 100 条用户消息，另参考机器人回复；扫描最多 200 条记录，材料约 24,000 字符，单条最多取 800 字符。

每天最多调用 12 次，按北京时间换日，失败也计次数。每次最多提出 3 条表达习惯，需有可追溯的真人示例；可新增、修正或丢弃。固定身份、权限和工具规则不能被学习改写。回复时最多选 3 条相关习惯、每条最多 2 个短示例，总注入约 1800 字符。

后台“立即学习”至少需要 2 条新用户消息、距上次调用至少 5 分钟，仍受每日上限约束。学习项可查看来源、编辑、停用、回退和删除。

## 图片怎样处理

| 环节 | 实际输入与保存内容 |
| --- | --- |
| 收到图片 | 后台排队让 DeepSeek 生成约 150 字的检索描述，持久保存最多 600 字符。 |
| 该条消息触发回复 | 原图与该条文字交给回复模型；无需等描述完成。 |
| 后续历史与摘要 | 只带图片编号、来源和文字描述，不自动再带旧原图。 |
| 按编号重看 | `inspect_chat_image` 从 QQ 取回选中的原图，附到本轮用户问题，再由同一个回复模型继续回答。工具本身不再调用一次视觉问答。 |
| 原图无法读取 | 明确说明没有核实到原图，已有描述只能参考，需要用户重发。 |

每张图片有稳定编号，例如 `img_200_1`。缓存区分 QQ 链接中的 `fileid` 等资源参数；只对有明确文件 ID 的 QQ 下载链接忽略可更新的访问密钥。不同文件不能共用描述。升级时旧错误描述及依赖的摘要／召回缓存失效，聊天原文、长期记忆和学习记录保留；历史图片描述在相关聊天再次使用时按需重建。

原图只在当前处理的内存中存在，来自 QQ 服务器，不在 NAS 落盘、不写入工具记录或后续聊天历史。每张最多 8 MiB，本次单轮原图上限 3 张，不压缩；只允许指定 QQ 图片域名的 HTTPS 链接，单次下载最长 10 秒，不跟随重定向。图片描述排队并发为 1、队列上限 32、排队时限 180 秒。重看工具时限 15 秒。

过程日志会区分“工具已取回并附图”和“模型本次附图 0／1／… 张”。有描述不等于本轮看过原图；用户要求评价原图或质疑看错时，提示词要求取回目标原图核实，不能拿之前的回答作证。判断与选图仍由模型完成。

## 发送、工具和定时任务

| 项目 | 当前参数或行为 |
| --- | --- |
| 聊天排队 | 同群／私聊逐条处理；不同会话最多并行 2 轮，等待队列上限 100，等待最多 120 秒；单轮处理最多 120 秒。 |
| 工具调用 | 每轮最多 8 次模型步骤；每步最多 8 个工具调用；同轮重复调用 ID 拒绝。普通工具默认 10 秒，工具自己的时限可覆盖；结果最多保留约 12,000 字符。 |
| 权限 | 根据 QQ 官方传入的真实用户 ID 鉴权，参数和提示词不能伪造身份。读工具通常开放，敏感写操作要求管理员。 |
| 网页搜索／阅读 | 默认搜索 5 个结果，正文每段 6000 字符，可继续翻页；单次工具最多 45 秒。 |
| MCP／Skills | MCP 工具默认仅管理员可用，明确列为公开且声明只读的才开放；Skill 脚本另有开关，当前关闭。 |
| 私聊流式 | 更新同一条 QQ 消息，约 500 毫秒更新一次；结束发完成状态。 |
| 群聊流式 | 按句号等句末标点／换行发送前四段，第五段合并余文；每段最多 1500 字符。 |
| 回复过长 | 超出第五条容量时报告未发送余文并记录失败，不静默假装已发完。 |
| 发送异常 | 保存发送意图与 QQ 回执；结果未知不自动重发。明确召唤的处理失败每轮最多尝试一次 QQ 故障提示。 |
| 定时提醒 | 每秒检查到期任务；支持一次性、每天、每周，默认北京时间，发回创建任务的聊天。到点直接发送文字，不调用模型。 |
| 提醒频率保护 | 每个目标每分钟最多 15 条、全局每分钟最多 25 条；仍受 QQ 官方权限与总额度约束。 |

停机错过的提醒恢复后补发一次，重复任务安排下一次未来时间，不把所有错过周期连发。发送中断、结果未知的提醒不自动重发；普通用户管理自己的提醒，管理员可管理当前聊天的任务，后台可查看和取消全局任务。

## 在哪里看、改和追查

内网面板：`http://192.168.31.97:18081/`。外网面板：`https://nas.doebkblcya.com:48393/`。两者验证原有长 Key，公网保持 HTTPS；保存配置后应用并重启生效。

- 聊天记录：按群聊／私聊分类，每页 50 条，包含没触发回复的消息；可以备注名称、看处理详情、彻底删除消息或会话。
- 记忆与学习：查看、纠正、删除及追溯来源；删除同时清理相关版本／索引和可追溯的派生数据，不把旧内容留作可检索的删除标记。
- 过程日志：面板保留本次启动最近 500 条，每 2 秒刷新；完整运行输出由 Docker 日志保存，最多 3 个 10 MiB 文件。
- 模型用量：SQLite 持久保存每次真实 HTTP 请求，流式读取末包用量，重试逐次计数。按功能／模型／日期汇总，明细每页 50 次，可关联聊天回复；独立看板可见时约每 10 秒刷新。
- 用量缺失：断流或接口没返回统计，记为未知，不算零。缓存命中包含在输入中，思考包含在输出中，不重复相加。余额和剩余额度以平台账单为准。

应用目录是 `/vol1/1000/sys/docker/xiaolang`，数据和外挂插件分别挂载到 `/app/data`、`/app/plugins`。当前只运行一份小狼实例，容器内存上限 512 MiB；发布时由 NAS 直接下载 GitHub Actions 已检查的镜像，校验后更新，保留当前与上一版镜像。原图和凭证不会写进这份文档。
