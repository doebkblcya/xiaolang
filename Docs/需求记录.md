# 小狼要做成什么样

更新日期：2026-10-20。看当前完成情况请到 [实现进度](实现进度.md)，看消息怎么处理请到 [主链路](主链路.md)。

## 已确定的方向

小狼是自己日常使用的 QQ 聊天伙伴：有统一的人设，说话自然、轻量克制，也能按需要做一些事情。项目计划开源。

- 使用 TypeScript＋Cordis 4 自行编写，主链路和后续能力都按插件组织。成熟项目用来参考，合适的基础库直接复用。
- 使用 QQ 官方机器人和 WebSocket，直接在正式环境、自己的私聊和测试群联调。不再做 OneBot／NapCat 接入。
- 文字回复使用 DeepSeek V4.1 Flash，当前模型标识为 `deepseek-flash`。所有群共用一个人设。
- 优先方便自己扩展，暂不建设第三方插件市场，也不增加多平台目标。
- 在飞牛 NAS 上用 Docker 运行，Mac 只做开发。VPS 已结束使用并清理；现有 AstrBot／NapCat 不动。
- 私聊默认回复；群里 @ 小狼，或者句中任何位置出现触发词，就触发回复。主动插话需要独立开关。
- 插件列表展示内置和外挂插件；两类都允许启停，显示依赖与停用影响，不额外禁止。插件能声明自己的配置，在详情里编辑。
- 后台聊天记录按群聊、私聊分会话查看，包含未触发回复的消息，支持搜索、备注和历史翻页；处理详情附在对应消息上。
- 模型用量按功能分别统计，显示每次实际请求的输入／输出 Token、缓存命中、思考 Token、耗时和失败；可按日期、服务筛选。流式、后台调用和重试均记录，用量未知不记成零。
- 本轮先实验 high：聊天回复、记忆提炼、摘要、表达学习；图片短描述和插话判断关闭思考。历史只带图片描述，重看工具按编号取回原图交给当前回复模型，不再另找模型转述。旁观判断改为 60 秒或 20 条。
- 面板支持外网访问，沿用 NAS 已有 DDNS 域名加端口，通过 HTTPS 和单个长 Key 验证身份，不建设账户／用户系统；复用 NAS 同域名证书。

## 后续功能与已定方向

以下按实际需求和已有代码整理，方便按大模块讨论；不是固定的插件数量，也不是用户举例的穷尽清单。实现时继续补齐遗漏，调整分组。

| 工作方向 | 要做什么 | 方向与讨论状态 |
| --- | --- | --- |
| 记忆（包含聊天上下文） | 收集所有实际收到的聊天，结合近期原话、摘要、人物资料和重要经历理解对话；支持图片、现实时间、自动回想与主动检索，以及记忆管理。 | 已定：AI 自动判断、整理和更新；人物及经历全局共享，保留来源，由模型选择使用；采用关键词＋向量混合检索，向量服务使用阿里云百炼外部 API。完整方案见 [主链路](主链路.md#记忆模块最终方案)。首版进度见 [实现进度](实现进度.md)。新增、补充、状态替代和忽略在同批提炼中判断；默认召回当前版本，历史按需读取，后台可查看变化。图片原图由 QQ 托管，小狼保留编号、链接、短描述和来源，按需通过工具重看。 |
| 人设与学习 | 做完整的人设插件，统一身份、性格和回复风格；按设定学习聊天中的表达习惯。学到的知识归记忆，表达习惯影响人设。 | 已定：四个多月的母猫、彩狸、中华田园猫，带幼童感，微傲娇偏高冷，也会粘人和生气。QQ 回复简短、不发散。基础人设只由用户修改；从所有收到的真人聊天里后台学习适合她的表达习惯，自动生效，支持查看、修改、停用和回退。人设学习与记忆提炼分别调用模型，互不合并请求。 |
| 工具与行动 | 让模型在约定范围内自主选择实用工具、组织执行步骤并反馈结果，不逐次询问；增加网页搜索与网页阅读工具，通过插件接入 MCP、Skills 和需要的脚本能力。 | 已定：先完成基础工具与接入口，不预设具体任务清单；网页搜索和阅读使用 DeepSeek Search／Fetch，MCP 与 Skills 分别作为插件接入。管理员按 QQ 官方用户 ID 配置，敏感工具由程序鉴权，只有管理员可执行。后续增加工具通过插件扩展。 |
| 主动互动与任务 | 主动插话放在触发插件；定时提醒、重复任务等可由工具创建，交给调度按时执行。 | 主动插话已定：独立开关＋群黑名单，开启后默认允许所有可接收消息的群；活跃时新消息尽快判断，旁观时按时间或条数合批，由模型结合近期对话决定是否参与；明确召唤仍直接回复。已实现轻量定时提醒：创建／查看／取消，一次性／每天／每周，默认北京时间、发回当前聊天；到点直接发送提醒文字，后台可看任务和执行结果。已有真实定时提醒获得 QQ 发送回执。 |
| 回复呈现 | 在“统一发送”插件选择普通／流式输出；流式时私聊使用 QQ 原生流式，群聊按句实时发送。 | 群聊最多五条，前四条逐句发送，第五条合并剩余内容；超过字数限制时明确提示。 |
| 表情包 | 自动收集表情包，并在合适时选用、发送，让它自然地参与聊天。 | 暂时搁置：用户希望原生表情包效果，目前 QQ 官方接入未找到对应发送能力，不以普通图片发送代替。 |

这些工作覆盖原来的触发与调度、人设与回复、规划与工具、Memory、图片、自学习、插件扩展、表情包、管理界面九项范围。插件基础和管理界面贯穿各项功能，随功能一起完善。

语音、注意力与行为学习、电脑操作暂不做。项目许可证和新增功能的开发顺序尚未确定。

## 哪些由助手直接负责

小狼项目内的调度、发送、异常处理、日志、存储、后台和插件运行维护等工程事项，由助手主动盘点、选择合理方案并完成，不要求用户逐项审批或讨论。排队、并发、合并／打断、取消、超时、重试和重启后的任务处理，都按实际需求由助手判断。

已有功能仍需维护。工程细节不单列成让用户选择的功能清单；相关工作记录在 [实现进度](实现进度.md) 的工程部分，完成后简短汇报。涉及上述产品体验、改变已确认需求或任务范围时，再集中讨论。

用户提出的是方向和例子，助手负责核对全部已有需求与实现，补充遗漏，不能把用户随口列出的几项当成完整清单或最终设计。

## 怎么推进

- 按大模块讨论体验，不逐个追问简单参数，不重复确认已确定内容。
- 先明确新功能要带来什么体验，再实现对应插件；日常工程完善可以同步推进。
- 小改动可以攒一批发布。需要镜像时由 NAS 直接下载构建产物；只改外挂文件或配置时按实际情况更新。每次部署确认正常后，小狼镜像只保留当前版本和上一版用于回退，清理更早且未被容器引用的版本，以及本次临时文件和辅助容器。
- 验证做到足以确认改动有效，基础改动不反复跑全量检查。环境、模型、消息范围等影响使用的变化主动说明。
- 保存配置后重启目前先保留，不在这次整理中改动。

旧路线与调研资料在 [初期调研](初期调研/)，只作参考，不作为当前实施要求。

管理面板支持彻底删除消息、会话、记忆和学习出的表达习惯；删除相应版本、向量和关联数据。基础人设是内部背景，不作为每次自我介绍的台词。官方返回群名或昵称时用于展示，空值保留 ID。
