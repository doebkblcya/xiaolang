# 记忆、上下文与表达自学习

更新：2026-10-24。本文说明当前机制与评估方法；数值集中见[运行参数](../总体链路与运行参数.md)，源码以 [memory.ts](../../src/memory.ts)、[memory-store.ts](../../src/memory-store.ts)、[persona.ts](../../src/persona.ts)为准。

## 四类内容各做什么

| 内容 | 用途 | 是否调用模型 |
| --- | --- | --- |
| 聊天原文 | 已接收消息、已确认回复及平台结构，构成近期对话和来源证据。 | 保存与浏览不调用。 |
| 会话摘要 | compact 较早对话，让有限上下文接续历史，不删除原聊天。 | 达到压缩条件时独立调用。 |
| 长期记忆 | 人物事实、持续偏好、重要经历或计划；跨会话共享，保留来源、时间与版本。 | 后台提炼；回复前可做向量检索。 |
| 表达习惯 | 特定情境下可迁移的表达顺序、语气与节奏。 | 后台学习；回复时只选用已有内容，不额外学习。 |

主人格与固定回复风格来自人工配置，学习不能覆盖。记忆和学习共用模型服务，但拥有独立调度、Prompt、游标和存储，不互相触发对方请求。

## 回复时模型实际看到什么

固定人设与规则 → 会话摘要 → 尚未压缩的近期原文 → 本轮召回记忆与表达参考 → 当前时间、发言人及初始附图状态 → 当前消息和实际原图。工具定义在当前权限范围内稳定排序；后续工具结果随调用链追加。

聊天页和模型输入使用同一归一化消息、引用正文与后台图片描述。模型输入还包含系统规则、摘要、召回、权限及预算限制，因此聊天页面不是完整 Prompt 的逐字副本。引用缺失、图片描述尚未生成和原图过期要明确显示，不能编造未收到的内容。

会话摘要弹窗默认显示按当前配置得到的“模型使用的摘要”，完整保存摘要可展开查看；当前会话摘要不是历史某轮的快照。历史轮次的实际摘要与召回列表由 `memory_recalls` 保存，但会受人工清理及保留窗口影响。

## 插话判断的候选与历史

候选 `candidates` 是这次要决定回不回复的新消息，必须保持完整；历史 `recent` 只负责解释人物、引用和前后关系，不是可供模型选择的目标。这个缩减只用于轻量插话判断，**不把正式聊天的历史限制改成 1800 Token**。

- 历史通常从最近配置条数选取；可补查当前候选顶层引用指向的同会话原文，不读未来消息，不跨会话拼接。
- 已在候选里的消息不重复加入；候选内已有完整引用正文时不再复制该引用。
- 依次优先引用目标、最近小狼发言、紧邻对话、相邻辅助内容和其他历史；最终按 seq 时间顺序排列。
- 历史 JSON 最多 1800 Token，动态输入整体最多 6000 Token。重要引用单条约 900 Token、小狼发言／紧邻历史约 500、其他约 300；重要长片段标记 `truncated`，不重要的超长历史可省略。
- 候选装批预留额外字段空间，单条无法容纳时跳过并记录 `proactive_candidate_too_long`，不截断后假称完整候选。
- 固定判断规则和身份在前，历史在前于候选、模式和当前时间，有利于前缀缓存；没有增加模型调用来压缩历史。

当前 Prompt 允许公开话题、近况、观点与合适的梗，要求分清说话人和被问对象；不是只有点名或解决问题才参与。同话题不逐句点评，多选用于不同有效回应点。只输出选中 seq 与短理由，不输出长分析或未选理由。

`proactive_judge_started` 显示批次大小、历史候选／保留条数、已内联引用、实际历史 Token 与预算。`proactive_decided` 按消息标记 selected、unselected 或 silent；同一批会为多条消息各记事件，因此事件条数不能直接当作 API 调用次数，应以用量或批次 ID 去重。

## 自动提炼如何触发

原始消息立即保存，图片描述独立排队。提炼从持久 cursor 之后扫描新用户消息；默认 **20 条立即处理，或最早一条等待 600 秒后处理不足一批的内容**，每批上限仍为 20 条。这个门槛不是“每分钟无论几条都提炼”，也不是聊天 compact 的触发阈值。

后续新消息不延后最早截止；启动检查积压，依据原消息时间恢复等待。正在处理时不并发启动同批；成功后推进游标，失败不推进并至少冷却 60 秒。被人工删除的来源不再自动生成同一记忆；全被抑制的材料可跳过并推进。手动整理可提前处理，仍不调用没有材料的空批。

输入顺序是既有相关记忆、去重背景、本批消息、当前时间。背景只补机器人已确认回复与历史，不重复本批消息；来源只能指向本批用户原文。正文有批次／单条预算，不能把入库解释为完整无上限重读整个数据库。

模型一次可给 add、update、supersede、ignore，最多 12 条候选。程序校验人物、来源、旧条目与版本；同一旧记忆一批不重复修改。普通补充与状态变化保留历史；人工纠正使错误旧版本不再可召回，不能把更新时间当作事实发生时间。

当前 Prompt 要求：

- 持久事实、偏好和有意义的计划才保存；普通指令、寒暄、单次情绪或重复消息可返回空结果。
- 不把关系玩笑、调侃认成真实亲属；不从一句技术建议给人贴职业／能力标签。
- 引用、转发和图片描述中的人物，不能直接归到发图者；不确定则不保存或明确不确定。
- 计划、进行中与完成分清；新状态和新增独立事件分清；没有新证据不重复覆盖。

`memory_processing_completed` 区分实际处理条数、候选条数、有效写入与重复忽略。候选为零可以是正确拒绝低价值材料；只看调用次数不能评价质量。

## 检索与真正使用

正式回复准备上下文时，用当前消息和少量最近入站内容构造查询，先生成向量，再结合 SQLite 全文检索、人物资料及置顶项做融合排序。默认最多 8 条，另受摘要与记忆共用字符预算限制；排除过期记忆，保留归属与来源标签。人物资料属于补充参考，因此“召回 8 条”不代表 8 条都与当前话题高度相关。

百炼向量接口一般时限 15 秒，前台召回最多等待 2.5 秒；失败退回仍可用的关键词／人物路径，并记录 `memory_vector_fallback`。没有向量密钥时同样可用文字检索。向量索引可重建，正文不依赖向量服务容器。

| 证据 | 能证明什么 | 不能单独证明什么 |
| --- | --- | --- |
| 用量中的 `embedding_recall` 成功 | 向量接口实际完成请求。 | 命中了正确记忆、模型使用了记忆。 |
| `memory_recalled` | 本轮已选入若干记忆及近期原文。 | 每条都相关、最终没有因后续预算变化而调整。 |
| 轮次的记忆／摘要快照 | 当轮上下文准备选中的内容与来源。 | 模型确实理解、最终回答完全正确。 |
| 原问题、快照与已确认回复一起核对 | 可以评估误召回、遗漏、归属与使用是否恰当。 | 没收到的历史、已清理快照或完整服务商内部 Prompt。 |

回复前的预算处理可能刷新摘要及历史范围；查看“当前摘要”不能冒充当时的完整输入。召回快照最多保留最近 500 轮。

## 表达学习如何把关

自动学习同时要求距上次尝试至少 30 分钟、有至少 20 条新用户消息；每批最多 100 条用户消息、扫描最多 200 条记录，材料约 24000 字符、单条最多取 800。北京时间每日最多 12 次，失败也计数且跨重启保存；手动调用至少 2 条新用户消息并有 5 分钟冷却。

学习 Prompt 先放固定人设、风格和既有习惯，再放新材料、当前时间。新建不带 id/version；更新原样带既有 id、当前 version，由程序递增，不能自增或传 null。每次 0～3 条，最多存 30 条，满额后仅更新。

每条 2～3 组不同回复的问答：同组必须同会话，prompt seq 小于 reply seq，差值不超过 15；reply 不能为小狼，两条都为入站消息时用户须不同。程序解析的 replyTo 是配对提示，序号接近不是语义对应的证明。

入站标成 human 仅说明来源不是本机器人，不保证由人手写。Prompt 排除其他机器人措辞、下载回执、系统播报、卡片标题、机械复读；学习有边界的方法，不把“没用过”“没影响”等固定答案或别人的现实经历套给小狼。停用项不会自动复活，证据不足可返回空列表。

回复时最多参考 3 条习惯、每条最多 2 个短示例，总量约 1800 字符。版本与证据可在面板查看、编辑、停用和回退；拒收按字段、版本、证据、重复及容量分类记日志。Prompt 不能替代真实样本验收，尤其其他机器人消息的语义识别仍需观察。

## 删除副作用与后续评估

面板删除单条记忆会清理其全部版本、全文索引、向量，并抑制来源再次提炼；**还会清除摘要、全部召回及压缩快照／重试记录**，避免旧副本继续进入上下文。原始聊天不删除。删除表达习惯清除该习惯的版本、示例关联并抑制旧来源重新学习；原聊天同样保留。删除消息／会话才按来源清理相关回复及可追溯派生数据；这些都是不可撤销的本地删除，不是 QQ 撤回。

2026-10-24 已清理旧的低价值产出。后续用户手动发起复查，不设定时提醒。复核应分别看有意义的新增事实、可迁移表达、拒收是否合理、真实召回相关性和成本；没有足够新对话时如实保留结论，不为填满记忆库或生成报告而手动调用模型。私人基线留在被 Git 忽略的 `data/`，不公开聊天或身份标识。
